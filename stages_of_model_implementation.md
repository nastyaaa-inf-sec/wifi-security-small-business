Внедрение комплексной модели информационной безопасности проектируемой сети реализовано в несколько последовательных этапов, каждый из которых формирует отдельный эшелон защиты.

На первом этапе выполнена сегментация сети на канальном уровне посредством создания четырёх виртуальных локальных сетей на коммутаторе SW-CORE-01. Каждый VLAN соответствует отдельной функциональной зоне: VLAN 10 выделен для административного управления сетевым оборудованием, VLAN 20 обслуживает корпоративных пользователей и внутренние серверные ресурсы, VLAN 30 предназначен для гостевых клиентов, а VLAN 40 объединяет устройства Интернета вещей и IP-телефонию. Порты коммутатора строго разграничены по принадлежности к конкретным VLAN, что полностью исключает неконтролируемое межсетевое взаимодействие на канальном уровне. Для транковых портов, обслуживающих контроллер WLC и точки доступа, применено ограничение списка разрешённых VLAN с указанием native VLAN 10, что эффективно предотвращает атаки двойного тегирования кадров 802.1Q.

Второй этап связан с внедрением механизмов защиты на беспроводном уровне. Для каждой из трёх созданных сетей на контроллере WLC 3504 сконфигурирован индивидуальный профиль безопасности на базе протокола WPA2-PSK с криптостойким алгоритмом шифрования AES. Ключевые фразы для сети персонала Corp_Staff, гостевой сети Guest_WiFi и сети устройств Devices_Net являются уникальными и не пересекаются между собой, что предотвращает компрометацию корпоративных данных при раскрытии гостевого пароля. Дополнительно в гостевой сети и сети IoT-устройств активирована функция Peer-to-Peer Blocking, запрещающая прямой обмен данными между беспроводными клиентами. Распределение точек доступа по группам с назначением конкретных SSID исключает трансляцию гостевой сети в офисной и складской зонах, равно как и корпоративной сети в публичном гостевом пространстве.

Третий этап заключается в конфигурировании расширенных списков контроля доступа на граничном маршрутизаторе. Список ACL 120, назначенный на подынтерфейс гостевого VLAN, последовательно блокирует любой IP-трафик в направлении административного, корпоративного и IoT-сегментов, разрешая только доступ к внешним ресурсам. Аналогичный список ACL 140 на подынтерфейсе VLAN 40 изолирует устройства Интернета вещей от критичных внутренних сетей. Применение расширенных списков доступа вместо стандартных позволило создать гибкую политику фильтрации с возможностью последующего добавления правил по конкретным протоколам и портам транспортного уровня.

Четвёртым, перспективным этапом явилось развёртывание RADIUS-сервера с выделением ему статического адреса в корпоративном сегменте VLAN 20. Данный шаг закладывает технологический фундамент для последующей миграции с аутентификации по общему ключу на протокол IEEE 802.1X с индивидуальными учётными записями пользователей, что качественно повышает уровень защищённости сети.

Заключительный этап охватывал верификацию всех внедрённых механизмов. Корректность сегментации подтверждена анализом таблицы VLAN на коммутаторе, а работоспособность ACL проверена экспериментально: устройствам вручную назначались IP-адреса из чужих подсетей с последующими попытками доступа к изолированным ресурсам, которые были полностью заблокированы, что подтвердило корректность настроек межсетевой фильтрации.
