# Модель защиты беспроводной сети малого предприятия

---

## Проблема

Малый бизнес строит Wi-Fi на потребительском (SOHO) оборудовании: гостевая сеть часто оказывается в одном широковещательном домене с корпоративной, IoT-устройства не изолированы, используются устаревшие протоколы шифрования. По данным исследований 2025 года, только 28 % МСП имеют в штате специалиста по ИБ, а 85 % инцидентов связаны с человеческим фактором. Атака на такую сеть — вопрос минут, а последствия для малого бизнеса могут быть критичны вплоть до остановки деятельности.

## Проделанная работа

Спроектирована и реализована в **Cisco Packet Tracer** эшелонированная модель защиты беспроводной сети малого предприятия. Модель формирует три рубежа обороны: канальный, сетевой и транспортный уровни.

### Сегментация сети (канальный уровень)
Четыре изолированных VLAN на коммутаторе Cisco Catalyst 2960-24TT (`SW-CORE-01`):

| VLAN | Назначение | Подсеть | Шлюз |
|------|------------|---------|------|
| 10 | Management | 192.168.10.0/24 | 192.168.10.1 |
| 20 | Staff (сотрудники, RADIUS, принтер) | 192.168.20.0/24 | 192.168.20.1 |
| 30 | Guests (гостевая сеть) | 192.168.30.0/24 | 192.168.30.1 |
| 40 | IoT_Devices (IP-телефон, уязвимые устройства) | 192.168.40.0/24 | 192.168.40.1 |

Транковые порты ограничены списком разрешённых VLAN, native VLAN 10 — защита от атак двойного тегирования 802.1Q.

### Централизованное управление (Cisco WLC 3504)
Три лёгкие точки доступа (`AP-OFFICE-01`, `AP-WAREHOUSE-01`, `AP-GUEST-01`) под управлением контроллера `WLC-MAIN-01`. Через механизм **AP Groups** реализовано зонирование: гостевая сеть не транслируется в офисной и складской зонах, корпоративная — в публичной зоне. Количество транслируемых SSID сокращено с 9 до 5 (−67 % видимой поверхности атаки).

### Шифрование и аутентификация (транспортный уровень)
Каждая WLAN настроена на **WPA2-PSK с AES** и уникальной ключевой фразой:

| SSID | VLAN | Интерфейс WLC |
|------|------|---------------|
| `Corp_Staff` | 20 | staff-interface (192.168.20.2) |
| `Guest_WiFi` | 30 | guest-interface (192.168.30.2) |
| `Devices_Net` | 40 | iot-interface (192.168.40.2) |

Для гостевой и IoT-сетей активирована функция **Peer-to-Peer Blocking** — запрет прямого обмена данными между беспроводными клиентами.

### Межсетевое экранирование (маршрутизатор `GW-MAIN-01`)
Расширенные ACL на подынтерфейсах (Router-on-a-stick):
- **ACL 120** на `Gi0/0.30` — блокирует трафик из VLAN 30 (гости) в VLAN 10, 20, 40, разрешает выход во внешние сети.
- **ACL 140** на `Gi0/0.40` — блокирует трафик из VLAN 40 (IoT) в VLAN 10 и 20, разрешает доступ в гостевую сеть и интернет.

### Задел на 802.1X
RADIUS-сервер `SRV-RADIUS-01` (192.168.20.100) развёрнут в VLAN 20 — технологический фундамент для последующей миграции с PSK на IEEE 802.1X с индивидуальными учётными записями.

Все проверки выполнены в режиме Realtime в Packet Tracer; для ACL-проверок ноутбуку `STAFF-LAPTOP-01` временно присваивался статический адрес из изолируемой подсети.

| 2 | Ping шлюза VLAN 20 с ноутбука | 0 % потерь | 0 % потерь, 7–44 мс ✅ |
| 3 | Ping принтера `PRN-OFFICE-01` (192.168.20.101) | 0 % потерь | 0 % потерь, 10–54 мс ✅ |
| 4 | Ping RADIUS-сервера (192.168.20.100) | 0 % потерь | 0 % потерь, <10 мс ✅ |
| 5 | Ping WLC из `ADMIN-PC` (192.168.10.2) | 0 % потерь | 0 % потерь ✅ |

## Ограничения лабораторной среды

Cisco Packet Tracer **не эмулирует полный стек CAPWAP**, поэтому лёгкие точки доступа (`AP-OFFICE-01`, `AP-WAREHOUSE-01`, `AP-GUEST-01`) не регистрируются на контроллере и не транслируют SSID. Для верификации VLAN-сегментации, DHCP и ACL в проект введена автономная точка `AP-DEMO-01` с идентичной конфигурацией безопасности в VLAN 20. На реальном оборудовании конфигурация WLC работоспособна.

Также выявлены ограничения Packet Tracer:
*   отсутствие **Rogue AP Detection** в эмуляторе;
*   отсутствие **PoE** на Catalyst 2960-24TT (потребовались внешние адаптеры питания);
*   штатные адаптеры `Laptop-PT` несовместимы с WPA2-PSK/AES — заменены на **WPC300N**;
*   GUI IP-телефона 7960 статичен и не отображает полученный по DHCP адрес (факт получения подтверждён через `show ip dhcp binding`).
